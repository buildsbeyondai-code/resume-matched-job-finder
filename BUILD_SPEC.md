### Key user journeys (one per line)

J1 Upload resume: open app (empty state: 'No resume yet' + upload button) -> upload PDF/DOCX -> loading indicator while parsing -> extracted skills, titles and years of experience shown for review/edit -> save. Error state: unreadable/oversized file shows reason and retry.
J2 Search jobs: set country, remote/hybrid/on-site, skills, keywords -> run search -> loading state with per-source progress -> results list. Empty state: 'No jobs match' + suggestion to widen filters. Error state: failed sources named in a banner while results from other sources still show.
J3 Review ranked matches: results sorted by match score (0-100) -> open a job -> see matched and missing skills and a link to the original posting.
J4 Save/dismiss jobs: bookmark or hide a job -> saved list persists across restarts (empty state when none saved).
J5 Refresh: re-run the last search; new postings marked 'New' and duplicates across sources merged.

### MUST-have features (one per line)

M1 Resume upload (PDF, DOCX) with local text extraction of skills, job titles and years of experience; user can edit the extracted profile
M2 Job search across configured sources filtered by country, work mode (remote/hybrid/on-site), skills and keywords
M3 Job sources limited to official/public APIs (e.g. public ATS job-board APIs of large employers, licensed aggregator APIs); no scraping that breaks site terms
M4 Match score (0-100) per job against the resume profile, results sorted by score, with matched and missing skills shown
M5 Duplicate postings across sources merged into one result
M6 Each result links to the original posting (apply happens on the employer site)
M7 Loading, empty, error and partial-failure states for upload, search and results
M8 Searches, results and resume stored locally in SQLite; resume never sent to third parties without explicit opt-in

### SHOULD-have features (one per line)

S1 Save/bookmark and hide jobs, persisted across restarts
S2 Filter results further by posting date, company and minimum match score
S3 'New since last search' marker on refresh
S4 Configurable list of target companies (MNC list) and sources
S5 Light/dark theme following system preference with manual toggle

### Acceptance criteria: Given / When / Then (one per line)

M1: Given no resume is stored, when the user uploads a valid 2-page PDF, then within 5 s the app shows extracted skills, titles and years of experience in an editable form.
M1-error: Given the user uploads a 15 MB or corrupted file, when parsing fails, then an error message states the reason (size/format) and the upload control stays focused for retry.
M2: Given a saved resume, when the user searches with country=Germany, mode=Remote, skills=Python, then every result shown has country Germany (or remote-eligible for Germany) and work mode Remote.
M2-empty: Given filters that match no postings, when the search completes, then an empty state 'No jobs match these filters' with a 'Widen filters' action is shown.
M3: Given the configured sources, when a search runs, then requests go only to the allow-listed API endpoints (verified by test with mocked network).
M4: Given a resume with skills {Python, AWS, SQL}, when results load, then a job requiring all three scores higher than a job requiring none, results are in descending score order, and each card lists matched and missing skills.
M5: Given the same job returned by two sources (same company, title, location), when results load, then it appears once with both sources listed.
M6: Given a result, when the user activates 'View posting', then the original posting URL opens in a new tab.
M7: Given one source times out, when the search completes, then results from the other sources are shown and a banner names the failed source with a retry action; during the search a loading indicator with per-source status is shown.
M8: Given a resume was uploaded, when the network traffic of upload and search is inspected in tests, then no request contains resume text, and the resume and results persist in the local SQLite file after restart.
